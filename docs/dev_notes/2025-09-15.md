The predict fallback branch in `ModelService.predict()` directly zipped model predictions with `category_names` without handling size mismatches. When the model outputs fewer categories than expected (e.g., 35 vs 36), `zip()` silently drops the missing categories, returning incomplete results that can break clients expecting all categories.

### **Solution Implemented**
Added category padding logic in the predict fallback branch (`app/services.py:365-384`) to ensure all expected categories are present:

```python
# Apply category padding logic for predict fallback
model_output_count = len(raw_predictions)
expected_count = len(category_names)

if model_output_count != expected_count:
    if model_output_count < expected_count:
        # Model outputs fewer categories - pad with zeros
        classification_labels = list(raw_predictions) + [0] * (expected_count - model_output_count)
    else:
        # Model outputs more categories - truncate to expected count
        classification_labels = list(raw_predictions[:expected_count])
```
