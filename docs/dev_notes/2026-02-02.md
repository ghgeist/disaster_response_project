**1. Manual dispatch appears mid-feed**: Even though manual dispatches were prepended in state, they appeared in the middle of the rendered feed. Debugging showed a reconciliation/order issue rather than a data-order problem.

**Resolution**: Adjusted the feed item key to include ordering context (composite key with index) so React preserves the array order in the DOM; added a render-order smoke test for `FeedPanel`.

**2. Manual dispatches lost when filters change**: When `selectedFilters` changed, the `useEffect` triggered a server fetch that completely replaced the `signals` state, causing all manually dispatched items to be lost. This contradicted the UI indication that "Dispatched items appear in Live Feed" suggesting persistence.

**Resolution**: Modified the feed fetch `useEffect` to preserve manually dispatched items (those with IDs starting with "MANUAL") when merging server-fetched data. Manual dispatches are now extracted from current state and prepended to new server results, ensuring they persist across filter changes.

## **Memory & Caching Considerations**

### **Current Design (Prototype-Acceptable)**

**Manual Dispatch Lifecycle:**
- Manual dispatches are stored in React state (`signals` array) and prepended to the feed
- **Ephemeral by design**: Manual dispatches are lost when:
  - Browser is refreshed (expected for prototype)
  - Filters are changed (triggers full API refetch, replacing entire `signals` array)
  - Component unmounts or state resets
- **Acceptable for prototype**: User confirmed that messages disappearing on refresh is fine

**Memory Management:**
- Manual dispatches accumulate in memory until filter change or refresh
- No bounds checking: If many dispatches are made without changing filters, the `signals` array grows unbounded
- Display is limited to 15 items via `filteredSignals` useMemo, but underlying state array continues growing
- **Risk**: In extreme cases (100+ dispatches), could impact performance, but unlikely in normal prototype usage

**State Management Pattern:**
- `App.tsx`: Filter changes trigger `setSignals()` which **merges** manual dispatches with server results
- Manual dispatches added via `setSignals(prev => [newSignal, ...prev])` (line 183)
- When filters change, the `useEffect` (line 71-92) fetches fresh data and preserves manual dispatches by extracting them from current state before merging with server results

**No Caching:**
- No localStorage/sessionStorage persistence
- No browser cache for manual dispatches
- All state is in-memory React state

**Recommendations for Production (Future):**
- ✅ **Implemented**: Merging manual dispatches with API results instead of replacing (fixes filter change data loss)
- Add bounds checking (e.g., max 50 manual dispatches, oldest removed)
- Optionally persist manual dispatches to sessionStorage for refresh resilience
- Consider backend persistence for manual dispatches if they need to survive across sessions
