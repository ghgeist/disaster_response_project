# Experiments

This directory stores experiment inputs, run outputs, comparison reports, and archived production metadata. If you are trying to understand how a model was tuned, evaluated, or promoted, this is the first place to look after `model/`.

## What Lives Here

- `experimental_runs/` for dated run artifacts
- `experimental_configs/` for reusable input configs and search spaces
- `model_candidates/` for parameter sets that are ready to feed into training scripts
- `comparisons/` for generated comparison reports
- `model_archive/` for archived production metadata and thresholds
- `logs/` for standalone experiment logs
- `results/` as a legacy output location used by older workflows

## Fast Navigation

- Looking for the latest candidate run: check `experimental_runs/`
- Looking for a ready-to-use parameter file: check `model_candidates/`
- Looking for hyperparameter search spaces: check `experimental_configs/hyperparameters/`
- Looking for comparison output: check `comparisons/`
- Looking for promotion history or archived thresholds: check `model_archive/`

## `experimental_runs/`

This is the main output area for dated experiment artifacts. Folders are usually named by date, sometimes with a descriptive suffix when a run had a specific purpose.

Examples you will see in this repo:

- `2025-11-06/`
- `2025-11-06-vocab15k-promotion/`
- `2026-01-22/`

Inside a run folder, expect some mix of:

- `performance_metrics.csv`
- `training_log.json`
- `MODEL_INFO.json`
- `PROMOTION_INFO.json`
- `label_order.json`
- threshold files such as `*_thresholds.json`
- model artifacts such as `*.pkl`

Some runs also use subfolders for related work on the same day, for example hierarchy tuning or vocabulary comparisons.

## `experimental_configs/`

This directory holds reusable inputs for experiments.

Common subfolders:

- `hyperparameters/` for search spaces used by `scripts/02_training/02_test_hyperparameters.py`
- `sampling_strategies/` for sampler definitions
- `eval_sets/` for frozen evaluation identifiers

Think of this folder as the place where you define what to try.

## `model_candidates/`

This directory holds concrete parameter sets that are ready to use with training scripts.

Typical contents:

- optimized hyperparameter outputs
- vocabulary-size configs such as `vocab_15k.json`
- class-weight configs such as `class_weights.json`

Think of this folder as the place where you keep the current best-known settings or tested variants you want to train with directly.

## `comparisons/`

Comparison reports generated by evaluation scripts land here. Files are timestamped so you can keep multiple reports without overwriting older ones.

Example command:

```bash
python scripts/04_evaluation/compare_models.py
```

## `model_archive/`

This folder tracks archived production model metadata and promotion history. It contains snapshots such as:

- archive records
- promotion records
- archived threshold files
- archived `MODEL_INFO` files
- archived training metadata

Use this when you need to answer questions like:

- What was in production before the latest promotion?
- Which thresholds were associated with an older production artifact?
- When was a production model archived or replaced?

## Typical Workflow

### 1. Define a search or experiment input

Put reusable search spaces in `experimental_configs/`, or point training scripts at an existing candidate config in `model_candidates/`.

### 2. Run training or optimization

Examples:

```bash
python scripts/02_training/02_test_hyperparameters.py data/02_stg/stg_disaster_response.db
python scripts/02_training/03_create_experimental_model.py
python scripts/03_optimization/optimize_per_category_thresholds.py
```

### 3. Review outputs

Look in:

- `experimental_runs/` for dated run artifacts
- `comparisons/` for side-by-side reports
- `logs/` for script logs

### 4. Promote when ready

When a candidate is good enough, use:

```bash
python scripts/07_operations/promote_model.py experiments/experimental_runs/<run-folder> --dry-run
```

That promotion workflow reads the candidate run, validates it, and writes production-facing metadata into `model/` and archival records into `experiments/model_archive/`.

## Conventions

- Prefer dated folders in `experimental_runs/`
- Use descriptive suffixes when a plain date is not enough
- Keep run artifacts together so each experiment folder is understandable on its own
- Store reusable templates in `experimental_configs/`
- Store ready-to-train parameter sets in `model_candidates/`

Threshold file naming is not perfectly uniform across older runs, so expect to see both newer `*_thresholds.json` files and older threshold artifacts. Treat the folder contents as historical data first and naming rules second.

## Notes On Legacy Content

- `results/` is still present for backward compatibility with older scripts
- `2024/` under `experimental_runs/` reflects earlier project organization
- Some older files use naming conventions that no longer match the newer run layout

When in doubt, trust the actual dated run contents over the README.
